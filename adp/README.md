# Athlete Digital Passport (ADP): технический фундамент

ADP — следующая версия CloudPulse после конкурса (PRD v0.1). Эта папка — рабочая площадка для её кода. **До 06.11.2026 она ни к чему не подключена**: сайт её не собирает, в живую базу Supabase из неё ничего не запускается.

## Правила изоляции

| Что | Как обеспечено |
| --- | --- |
| Сайт не зависит от ADP | Корневой `tsconfig.json` исключает `adp`, `next build` сюда не смотрит. Ни одна страница сайта не импортирует файлы из `adp/`. |
| ADP не зависит от сайта | В `adp/tsconfig.json` нет алиаса `@/`: код ADP не может импортировать `lib/` или `components/` CloudPulse. Свой алиас: `@adp/*` → `adp/src/*`. |
| Живая база не трогается | Все таблицы лежат в отдельной схеме Postgres `adp`. SQL проверяется на тестовой базе, в рабочей Supabase не запускается до решения после конкурса. |
| Старая `profiles` не меняется | У ADP своя `adp.profiles`, привязанная к тем же аккаунтам (`auth.users`). |

## Правила продукта, которые код обязан соблюдать

1. **Матрица доступа = RLS.** Кто что видит, решает база, а не интерфейс.
2. **Без диагнозов.** Триаж только ищет красные флаги и блокирует нагрузку; вернуть полную нагрузку может только врач.
3. **Машина считает, человек решает.** Перенос контрольной система только предлагает, решает учитель.
4. **Без выдуманных чисел.** Нет данных — пишем «нет данных», а не 0.

## Как проверять

- Тесты TypeScript: `npm test` (Vitest сам находит `adp/**/*.test.ts` вместе с тестами сайта).
- Типы ADP: `npx tsc -p adp`.
- База и RLS: нужен локальный PostgreSQL 16 (не рабочая Supabase!):
  ```
  createdb adp_test
  psql -d adp_test -f adp/db/tests/000_supabase_stub.sql
  psql -d adp_test -f adp/db/migrations/001_init_adp_schema.sql
  psql -d adp_test -f adp/db/tests/001_rls_matrix.sql
  ```
  Последняя строка должна быть `ALL ADP RLS TESTS PASSED`. Тест работает в транзакции и всё откатывает.

## База данных (шаг 2)

12 таблиц в схеме `adp`: 5 из ТЗ (`profiles`, `academic_records`, `eligibility_statuses`, `reschedule_requests`, `safety_flags`) и 7 необходимых для матрицы доступа:

- связи `team_memberships`, `guardianships`, `teacher_assignments` — без них правило «тренер видит свою команду» не записать; создаёт их только сервер после подписанной формы согласия;
- `doctor_access` — доступ врача, который выдаёт сам спортсмен, максимум на 14 дней, отзывается в один тап;
- `check_ins` (ответы — видят только спортсмен и выбранный врач) и `daily_status` (цвет дня — для родителя и тренера);
- `grade_scales` — опорные точки перевода шкал (пример из PRD, ждёт утверждения школой).

Кто что пишет: чек-ины, цвет дня, флаги из чек-ина и статус допуска пишет только сервер (service_role) после движков на TypeScript. Клиент не может нарисовать себе зелёный день или спрятать красный флаг. Роли teacher / coach / doctor / scout нельзя выбрать самому — их выдаёт сервер.

Перед подключением к Supabase (после 06.11): добавить схему `adp` в Settings → API → Exposed schemas.

## Движки и компоненты (шаги 3–4)

- **AcademicEngine** — `calculateEligibilityStatus(studentId)`. Красный, если хоть один предмет ниже проходного балла ИЛИ среднее ниже порога; жёлтый — в пределах запаса над линией; без подтверждённых школой оценок — «нет данных», а не зелёный. Для каждого проблемного предмета считает, какая минимальная оценка нужна на следующей работе. В базу сохраняет только цвет и код причины.
- **TriageSafetyGuard** — `processCheckIn(answers)`. Дерево из PRD 3.1: признак для 112 → удар по голове → боль → всё чисто. Любая боль сразу даёт красный и блок нагрузки, пропуск и запись к специалисту со сроком. Неснятый врачом красный флаг держит блок, даже если сегодня «всё хорошо». Сначала пишется блок, потом ответы: если запись сорвётся посередине, спортсмен уже заблокирован. Диагнозов нет — это проверяет отдельный тест.
- **PlayerRadarCard** — радар «ты сейчас против себя месяц назад». Сравнения с другими игроками нет вообще (нет даже такого параметра). В режиме `audience="shared"` ось «Восстановление» (данные о здоровье) не показывается. Нет данных — нет фигуры, только известные точки; ноль не рисуется. Каждая ось дублируется текстом со словом тренда — для экранного диктора и при дальтонизме.
- **TeacherRescheduleCard** — одобрение одним нажатием на предложенную дату; отказ в два нажатия, потому что он окончательный. Медицинская причина показывается без подробностей, даже если они пришли. Компоненты не ходят в базу сами: страница передаёт `onApprove` / `onReject`.
- Тексты на RU / LV / EN — `src/components/labels.ts`; компилятор проверяет, что во всех трёх языках есть все ключи.
- Все пороги и сроки — черновик из PRD, их утверждает врач клуба (`TRIAGE_RULES`) и соглашение школы с клубом (`DEFAULT_ELIGIBILITY_POLICY`).
